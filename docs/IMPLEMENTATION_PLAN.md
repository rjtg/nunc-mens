# Implementation plan

Baseline: Git commit `e67a0d9` and [Issue #1](https://github.com/rjtg/nunc-mens/issues/1). Reviewed README, AGENTS, REPO_FIFO, ARCHITECTURE, CLI, and ROADMAP. The FIFO specification and the issue supersede conflicting language about daily journals, exact keyword matching, ranking fusion, and storing no vectors. The executable is `nunc`.

## Architecture and scope

- One Cargo package with a library for shared logic and a thin CLI binary. Dependencies flow from CLI orchestration toward repo/config, entries, ingestion, and indexing/search. The repository layer owns canonical paths and configuration, entries owns Markdown encoding and atomic publication, protocol owns the parser, and the Unix runtime owns FIFO streams and locks. Source discovery and chunking build a common document snapshot for the index. SQLite owns its schema, transactions, and vector codec. An embedding interface permits deterministic tests, with fastembed as the production implementation. Ranking operates on compatible vectors and document provenance.
- Discover the worktree with Git from the working directory, including linked worktrees. Fall back to the canonical current directory outside Git or accept an explicit `NUNC_REPO_ROOT`. Hash the canonical worktree path into a repository ID. Store the index at `$XDG_STATE_HOME/nunc-mens/<repo-id>/index.sqlite3` and model under `$XDG_CACHE_HOME/nunc-mens/models`, with documented overrides and home-directory defaults. Reject index/model paths inside the active worktree.
- Source flags on init, serve, and reindex replace the configured list when supplied. Persist a validated, deduplicated, repository-relative list in `.nunc/config.toml` so offline reindex can reproduce the same scope. Without flags read the current config. Search flags only filter existing source provenance.
- Linux and macOS are the Unix implementation targets. Linux is the primary verification platform. POSIX FIFO and advisory file locks define the support boundary. ONNX Runtime distribution and target availability must be checked during the build. Cargo uses minimal text-only fastembed features and bundled SQLite. Git is required for Git-specific discovery and ignore behavior.
- CLI usage and invalid user input are distinguishable from operational failures. Annotate IO/SQLite/model failures with action and path where applicable, keep diagnostics off structured stdout, and keep content out of errors. A corrupt entry fails the snapshot and leaves the old index intact. Missing model is explicit and does not gate capture.

## Authoritative storage and derived index

- One `.nunc/entries/<uuid>.md` per note. YAML front matter is a JSON object (valid YAML) on a single line between LF marker lines. Version, UUID, RFC3339 timestamp with offset, optional repository context and tags form the header. Read the remaining UTF-8 body verbatim, including final newline state and CRLF. Only the fixed initial header is parsed. Verify ID and filename agree. Blank/oversized input fails before publication.
- Share an atomic file helper. Set permissions on same-directory temporary files, write and sync bytes, publish without clobbering an existing UUID, then sync the parent directory. The durable file path is shared by FIFO server, direct writes and logs. Runtime directory is private. Create a local ignore file protecting generated entries by default while keeping explicit force-add available.
- Build a deterministic snapshot from entries and selected files only. Git drives tracked/nonignored paths, source discovery deduplicates overlapping roots, excludes internal/build paths, ignores symlinks and special files, and enforces a UTF-8 text and size policy. Use the same validated repository-relative path type rules for filters. Preserve one-based inclusive original line ranges, including when a long line must be split. Use bounded, UTF-8-safe line-aware chunks and define deterministic chunk IDs from path, chunker version, and chunk ordinal; entry UUIDs remain stable across rebuilds. Content SHA-256 determines reuse and a snapshot digest captures metadata/scope freshness.
- SQLite starts at schema version 1 using user_version and transactional schema creation. Metadata fixes repo ID, model ID/revision, dimension and snapshot digest. Document rows store ID, kind, source path, text and hash, timestamp or line ranges, and vector. Store exactly dimension × 4 bytes as little-endian IEEE-754 f32. Reject length mismatch, non-finite numbers and zero vectors.
- Incremental reconciliation identifies unchanged text by ID and hash, updates metadata, embeds changed text in bounded batches and deletes absent rows. A serialized index writer and transaction prevent a failed refresh from publishing partial changes. Full rebuild stages a separate DB, validates and syncs it, then replaces the live DB with filesystem coordination. Readers use the same lock domain. Model, schema and corrupt database failures direct users to a full rebuild. The server and explicit refresh share this service.
- A background polling watcher under serve snapshots configured files and entries at a documented interval, with one refresh in flight and diagnostics on failures. Disk remains the pending queue across restarts. Search compares the current snapshot to committed index metadata and reports freshness warnings. Offline reindex refreshes without a server.

## FIFO

- A private runtime directory and owner-only POSIX FIFO/session metadata, one lifetime ownership lock per worktree, and a distinct lock for cooperative writers. Locks are permanent files whose advisory lock ownership is process-scoped. Restart removes stale artifacts only after verifying file type/ownership and winning the server lock. SIGINT/SIGTERM request orderly shutdown. A bounded polling reader can observe signals and writer EOF without a permanently open self-writer.
- Use a UUID v4 random token or an explicit 1–70 character ASCII alphanumeric/hyphen/underscore boundary. Only a complete LF or CRLF line equal to `--<boundary>` commits a frame. The bounded incremental parser handles arbitrary read splits, multiple messages, invalid UTF-8, oversized frames, empty frames and EOF. Discard an invalid oversized frame up to its next delimiter and clear incomplete state at observed writer EOF. The CLI rejects a collision before opening the pipe. Reserve a boundary-specific first-line marker for preserving CLI messages with no trailing newline, removing only the transport LF in marked frames. Raw FIFO writes preserve the LF before the delimiter.
- Serialize CLI clients and open FIFO nonblocking. Revalidate the current session and FIFO identity after opening. Use a bounded write deadline. If no bytes were accepted and there is no reader, write directly. After a partial transfer, return an explicit delivery error without replay; clients can use `log` to require a durable file receipt. Raw simultaneous writers need external serialization except for single atomic writes no larger than PIPE_BUF. A FIFO send reports queued bytes only; the server reports persisted entries and indexing status separately. Persist complete frames before any embedding work.

## Embeddings and search

- Fastembed 5.15.0 supports intfloat multilingual E5 Small via mean pooling on ONNX Runtime. Pin MIT-licensed `intfloat/multilingual-e5-small` revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`, 384 dimensions, CPU model `onnx/model.onnx`, and E5 query/passage prefixes. Use fastembed's local model constructor so offline commands have no downloader code path. Only `models download` uses HTTPS, stages pinned artifacts, validates the model, and publishes the cache atomically. HTTP transfer streams to disk. ONNX native distribution is a separate build/runtime prerequisite. Long documents preserve their full indexed text even when the model truncates at its token context.
- Embed one query, scan compatible stored rows in Rust and rank by cosine with f64 accumulators and deterministic ID tie-break. Keep at most K candidates. Filter by kind and repeatable literal repo-relative path/prefix using path components. JSON returns a single object with `mode_used`, `repo_id`, warnings and ranked result rows containing ID, path, kind, timestamp/line range, text, score and rank. A missing model yields an actionable failure; a current empty index yields empty results.

## Milestones and acceptance gates

| Phase | Scope and modules | Interfaces | Tests and acceptance | Prerequisites |
| --- | --- | --- | --- | --- |
| C | Cargo, CLI dispatch, repository paths and config | `Repo::discover`, config load/save, `nunc --help`, `init`, `status`, `doctor` | Nested and standalone roots, distinct state locations, config round-trip, clean build | Discovery and this plan |
| D | Atomic files, entry format, input and direct capture | `entries::persist/read`, `log`, shorthand, direct `write` | Exact bytes, tags, timestamps, duplicates, concurrent creation, invalid input, actual isolated capture | C |
| E | Parser and POSIX runtime | `serve`, `write`, session JSON and framing | Split and multiple frames, EOF, oversize recovery, collisions, concurrent clients, stale endpoints and restart; foreground binary persists real multiline text | D |
| F | Sources, deterministic chunks, vector codec and SQLite | Snapshot and embedder interface, `reindex [--full]` orchestration | Fake embeddings; ignored/overlapping/unsafe paths, changed/deleted files, rollback, isolation, incompatible vectors and atomic rebuild | C–D |
| G | Fastembed and semantic search | `models download`, `search`, JSON contract | Cosine and filters with fakes, explicit missing model failure, opt-in real E5 ranking with prepared cache | F |
| H | Watcher and integrated error recovery, product docs and CI | Server refresh and freshness diagnostics, reviewed CLI help | Integrated binary paths, no-model capture, refresh recovery, graceful shutdown, format/lint/test | E–G |
| I | Agent dogfooding and handoff | Isolated repository with real executable and cache | Record real FIFO and log bytes, explicitly prepare model, retrieve paraphrased note, verify source changes/deletions and stopped-server behavior | H |

Unit and integration coverage through F should require neither a model download nor model inference. The executable tests use temp roots, state and cache. Real ONNX verification is opt-in because the model is large. At each milestone review duplication, ownership, errors, hidden concurrency assumptions, public contracts and dependency scope. Record actual verification and any changes to the plan in the final handoff.
